# Boss 阶段、退场与非符计时

本记录对应 **v2.0.0 / 回放修订 13**。角色、攻击时长、血量及退场选择属于本作业务；实体运动、碰撞、武器、消弹、掉落、法阵、聚能、计时动画与警告音仍使用公共 thlib。修订 13 将半黑雾调整到道中入场第 40 帧，并加入首次关底立绘的名字介绍；保留既有移动曲线与首段非符不重复聚能。`GAME.contentRevision` 与 `GAME_REVISION` 同步，旧修订回放保留，但不按新规则播放。

## 道中 Boss 的阶段序列（v2.0.0）

导演把道中 Boss 统一建成阶段列表 `midbossPhases`，每个阶段是非符或符卡：

| 面 | 阶段 | 说明 |
| --- | --- | --- |
| 1 | 非符（30 秒） | 一面道中 Boss 只打招呼，击破或超时后飞离 |
| 2～6 | 非符（20 秒）→ 符卡（35 秒） | 非符结束后播放交接音 27，等待 40 帧进入符卡；符卡结算后飞离 |
| Extra | 三张符卡 | 御影房枝保持原有的三张封页符卡、卡间 60 帧，最后被击破 |

非符阶段使用公共普通血量与本作倒计时（`CampaignBossHud` 读取当前道中阶段的 `duration`），符卡阶段使用公共符卡血量、计时、收取与失败结算。非符阶段被击破时，只有它不是最后阶段才另给小份掉落，避免一面道中 Boss 双份掉落；符卡阶段照常掉落，最后阶段之后再走原有的道中退场掉落。新卡的记录编号为 35～39，原有 1～34 号不变，旧的符卡成绩不会错位。

## 中 Boss 飞离与最终击破

六面本篇的中 Boss 与该面最终 Boss 是同一角色。击破后停止攻击、消弹并按公共规则掉落，保留同一个可见实体，通过 `TouhouGame.beginBossEscape` 飞出；不启动死亡反色、死亡爆破或 `bossburst`。超时同样飞离，但没有普通击破奖励。飞离完成才移除实体，途中暂停会冻结位置与退场时钟。

击破路线目标为 `(192,-32)`，超时目标为 `(0,-32)`，飞离均为 60 帧、插值模式 4，即二次缓出 `1-(1-t)^2`。这些坐标使用公共的原作场地坐标。击破时立即停止战斗并撤下 Boss HUD，身体原地停顿 75 帧后开始飞离；超时没有这段停顿。同一个身体、法阵动画和背景扭曲对象在停顿与飞离期间持续更新，直到公共 `removeBoss` 实际移除实体才一并清理。道中时钟在 `midboss-exit` 期间停止，击破退出共 145 帧、超时退出共 70 帧，然后恢复道路编排。

身体始终通过公共 `bossPresentation.drawBody` 渲染，不再为停顿或逃跑绕过公共显示规则。`context.boss` 保留的是表现绑定；`stopBossCombat` 和公共 hold 独立关闭战斗就绪状态，玩家武器不能再伤害它，实体不能再造成接触伤害，导演也不再调用该阶段的弹幕。暂停同时冻结飞离、法阵和扭曲，恢复后沿用相同对象与时钟。

道中入场显式使用 `enterBoss(...,{profile:'midboss',entrance:{mode:'flyIn',readyFrame:100,follow:boss}})`，本体立即可见，并调用 `setBossEffects({aura:true,distortion:true})` 开启 effect99 与半径 128 的扭曲。从左上 `(-150,20)` 减速飞入 `(0,105)`；第 40 帧单独调用公共 `bossPresentation.beginEntrance({mode:'halfFog',readyFrame:60,follow:boss})`，不重新绑定 Boss 或重建光圈、扭曲。半黑雾使用原作 153/159/161 三组动画与一次音效 54，100 帧到点后再交给原有对话；中 Boss 对话只停战斗，不关闭这两个表现开关。随后主 Boss 必须重新指定 `profile:'boss'`，恢复 effect99/108 与半径 160 的扭曲；主 Boss 黑雾入场与对话期间关闭表现，在 `_beginPhase` 开始攻击时才显式开启。主 Boss 对话、结算和导演销毁明确关闭表现，不能依赖 `stopBossCombat` 隐式清除法阵。首段道中非符不再额外聚能；后续阶段每次聚能只播放一次。

原作 `st01mbs/st02mbs.ecl.txt:29–32` 是 100 帧 mode4 移动、等待 40 帧再开启 `EffChargePoint3`。`converging_particles.cpp` 中根节点跟随 Boss，但粒子的第二段终点在第一段完成时锁定，不会永远追赶。半黑雾第一段为 60 帧，40 + 60 正好对齐抵达时刻；出生就开雾会采到尚在移动中的位置，造成雾落后于身体。这里调整的是游戏演出调用时机，公共粒子路径和时长保持原样。

## 关底对话名字介绍

原作 MSG20 与 Boss 首次立绘同句触发名字动画。本作七位关底 Boss 在 `cues.portrait` 对应的对话句展示 `assets/boss-names/{bossId}.png`；最初指向场上实体的喊话仍不显示立绘与名字，道中和战后对话也不重复介绍。图片由内置 imagegen 生成，内容为本作称号、姓名与英文读法；原图、透明通道和来源记录保留在素材清单、`BOSS-NAME-PROMPTS.json`、`BOSS-NAME-SOURCES.json` 中。

参照 `st01enm` scripts17–20：前 60 帧由两组散字缩小并收拢，第 60～319 帧显示清晰牌，第 320～379 帧散开淡出；对话提前退出则用 20 帧淡出。游戏分组源图区域在 GPU 绘制，未生成或修改像素；散字分区是适配新文字的业务设计，并非原图逐像素复刻。名字居中于 640 基准坐标 `(320,370)`，等比限于 `128×64`，960 窗口对应 `(480,555)`、最大 `192×96`。通过公共对话队列放在第 37 层，位于立绘、气泡上方和正文下方；暂停冻结计时，反复绘制不推进动画或 RNG。

整个业务对话经公共游戏绘制队列的 UI 通道合成，暂停捕获和暂停菜单在其后绘制。不能在 `super.render()` 已画完暂停菜单后再追加立绘、对白或名字，否则会盖住暂停操作。名字仅拥有表现状态，原图由 `GameArt` 统一加载、释放，不向回放快照塞入纹理句柄。

本作在道中 `enterBoss` 中额外指定 `distortion:{color:TOUHOU_BOSS_PROFILES.boss.color}`，使扭曲颜色与关底一致。只覆盖颜色，道中半径128、effect99及持续时间仍沿用原配置；thlib 的公共 `midboss` 默认配色保持原样。

默认根据 `midbossSpec.bossId === stage.bossId` 选择 `escape`，不同身份默认选择 `defeat`；业务可显式配置 `midbossSpec.exit` 为这两种值。不同身份的真正击破仍保留公共死亡演出；不同身份超时则飞离。Extra 中 Boss 御影房枝与最终 Boss 玉继未央是不同角色，保留自己的三张符卡及最终击破。

原作参考不是“所有中 Boss 一律没有击破演出”：

| 原作脚本 | 击破路径 | 超时路径 |
| --- | --- | --- |
| `st01mbs.ecl.txt:176–211`、`st02mbs.ecl.txt:196–232` | 结算、掉落与消弹；小型击破反馈、震动和音效 5；等待 60 + 60 帧后以模式 4 飞向 `(192,-32)`，再等 60 帧移除 | `:215–234` / `:236–255` 取消阶段、消弹后以模式 4 飞向 `(0,-32)`；10 帧后撤下 Boss HUD，继续运动 50 帧 |
| `st04mbs.ecl.txt:535–552`、`st05mbs.ecl.txt:554–571` | 独立中 Boss：缓慢消弹，等待 60 帧，完成消弹并播放 25 / 57 号爆破效果后移除 | `:556–575` / `:575–594` 仍为 60 帧向上飞离，10 帧后撤下 HUD |
| `default.ecl.txt:22–56` | 通用 `BossEscapeNoDead` / `BossEscapeSpell` 保留独立退场路径，默认 60 帧模式 4 飞向 `(-224,-80)` | 结算、消弹、HUD 与掉落由调用方选择，飞离本身不承担死亡奖励 |

原作一 / 二面中 Boss 使用该面 Boss 的动画资源，四 / 五面使用独立中 Boss 动画库。还原脚本中三 / 六面没有对应的独立 `MBoss` 定义；本作三 / 六面中 Boss 是原创编排。当前版本按用户要求去掉再次登场角色的击破爆炸，采用 75 帧停顿后飞离，不复刻一 / 二面原作的 120 帧等待和小型击破反馈。它是有原作退场机制依据的业务演出选择，不能称为逐帧一致。

公共参考见 `packages/thlib/src/touhou/boss-escape.ts` 和 `game.ts` 的 `beginBossEscape`。TS-STG 的 Rush 示例在 `games/rushboss/src/runtime.ts` 的 `beginPracticeEscape` 中采用同一公共飞离序列；示例调用方先结算、消弹、停止聚能并隐藏战斗显示，退场完成后移除实体。本作直接使用公共 Game 的所有权接口。

## 阶段排布 `phaseLayout`

不是每张符卡前面都有非符。`src/content.ts` 里每个主 Boss 关卡有一条 `phaseLayout`，按战斗顺序写出各阶段：`N` 是一段非符，`S` 是下一张符卡（按 `spells` 的顺序取）。导演（`_buildPhases`）照这条字符串排出阶段；非符按出现顺序取 `nonspellNames` / `NONSPELL_PATTERNS` / `BOSS_NONSPELL_HEALTH` 里的第几组，符卡直接接在符卡后面时没有非符。

| 关卡 | 排布 | 非符 / 符卡 |
| --- | --- | --- |
| 一面 | `NSNS` | 2 / 2 |
| 二面 | `NSNSS` | 2 / 3（最后两张符卡连续） |
| 三面 | `NSNSNS` | 3 / 3 |
| 四面 | `NSNSNSS` | 3 / 4（最后两张符卡连续） |
| 五面 | `NSNSNSS` | 3 / 4（最后两张符卡连续） |
| 六面 | `NSNSNSNSS` | 4 / 5（最后两张符卡连续） |
| Extra | `NSNSNSNSNSNSNSNSSS` | 8 / 10（最后三张符卡连续） |

没有非符的符卡只出现在最后，每张独占一整条血条：前面先是若干「非符 + 符卡」对，最后才是连续的纯符卡。符卡接符卡时，上一张符卡结算后进入 60 帧的交接，下一张符卡拥有独立的血环（共享血环只在「非符→符卡」时存在，`TouhouBossPhasePlan` 自动按此分组）；交接时下一阶段使用符卡血量，而不是普通血量。排布必须以 `N` 开头，每个 `N` 后面必须是 `S`，`S` 的个数等于 `spells.length`，`N` 的个数等于 `nonspellNames.length`，由 `tests/content.test.js` 检查。

## 非符血量与共享血环

原作 ECL 的 `ins_511(totalHP)` 与 `ins_514(slot,nextSpellHP,duration,handler)` 表示共享血环中的当前非符和下一张符卡。非符实际伤害预算为 `totalHP - nextSpellHP`，不是把整组血量再给非符。本作继续使用公共 `TouhouBossPhasePlan`，没有改用 Rush 的业务显示权重，也没有在进入符卡时重新充满整个共用血环。

血环由公共 `TouhouBossHud` 渐进填充：原作 `hud_system/update.cpp:70–74` 每帧增加单精度 `0.025`，约 40 帧填满（第 41 次更新严格等于 1）；目标血量下降时立即钳至目标。游戏不再传入 `animateFill:false`。首次关底、道中与独立符卡练习从空环开始；非符进入同组符卡只保留剩余段，不再次填满。

本作在一个 tick 内结算上一组并预设下一组 HP，因此 `CampaignBossHud` 用真实 Boss 引用与 `groupIndex` 标记血环所有者，换组时显式清空显示进度；这是业务层适配，不代表原作每次 ECL511 都清空显示。原作暂时隐藏血环会保留显示比例。关底换组的 60 帧准备、道中换卡的 40 / 60 帧准备内就开始填充，进入攻击时不重置。被击破的实体仍由公共 hold 停止战斗，仅传给 HUD 的只读数据解除持有期间的显示抑制，真实 HP、伤害保护、接触碰撞与等待时长保持原规则。暂停冻结填充，受到伤害立即减少显示。

非符预算由 `src/boss-health.ts` 集中配置，原作出处和总量 / 阈值逐项写在源码注释中：

| 关卡 | 主 Boss 各非符 HP | 道中 Boss 非符 HP | 道中 Boss 符卡 HP（显示值） |
| --- | --- | ---: | ---: |
| 一面 | 12,000 / 12,000 | 11,000 | 无 |
| 二面 | 15,000 / 15,000 | 9,000 | 1,800 |
| 三面 | 20,000 / 20,000 / 19,800 | 10,000 | 1,950 |
| 四面 | 20,000 / 20,000 / 20,300 | 10,500 | 2,100 |
| 五面 | 16,000 / 16,000 / 16,000 | 12,000 | 2,250 |
| 六面 | 18,000 / 18,000 / 16,000 / 16,000 | 11,000 | 2,400 |
| Extra | 18,000 × 4，16,000 × 4 | 无 | 2,300 / 2,480 / 2,660 |

一面道中 Boss 仍是原作 `st01mbs:24` 的单独预算。二至六面因为非符之后还有一张符卡，非符预算约为旧版单独预算的三分之二，这是本作的节奏选择，不是原作数据。

六面第四段、Extra 第五段起超过对应原作非符组数（六面的原作第五组 13,000 因此不再使用），沿用该面最后一组预算。没有把这些扩展写成原作存在的攻击段。主 Boss 非符时限保留本作的 35～50 秒；道中 Boss 非符时限一面 30 秒、二至六面 20 秒（`MIDBOSSES[].seconds`）。

原作 `source_reconstruction/gameplay/enemy_damage_helpers.cpp:4–10` 在符卡状态中使用额外的储存血量比例，因此不能把非符预算直接乘 7。本次使用公共现有伤害单位，没有修改自机 DPS、敌弹判定、低速速度或武器实现。真实武器回归使用 Normal 一面、灵梦 / 魔理沙 P2 / P4、普通输入和碰撞，无 Bomb、无无敌、无 Miss，检查第一段 12,000 HP 非符能实际展开至少两轮攻击。它只证明这些样本的时长与战斗接入，不能代替六面及全部难度的真人平衡评价。

## 移动曲线与身体动画

道中入场使用公共 `AnmInterpolation` 的100帧mode4（二次减速），参考 `st01mbs/st02mbs` 的ECL401；保持本作左上出生点与目标坐标。原作常规60帧mode4和特殊回位mode9并存，不能把所有运动改成同一种曲线。本作换卡等待仍为60帧，使用mode9缓入缓出精确回位，替代每帧乘0.035追赶目标；开始轨迹前清除旧速度，等待结束后才进入下一段攻击。

原有正常游走的smoothstep保持。Extra的连续循环轨迹用公共mode9从实际位置接入，组合符卡分段结束前减速，修复了直接使用全局周期坐标造成的单帧约136单位跳变；发弹时刻、弹种、数量和随机数消耗保持，位置与瞄准随修正后的移动变化。

身体精灵使用游戏侧独立表现时钟，换卡、停留、对话和飞离时继续换帧；暂停冻结，绘制不推进时钟，也不修改Boss战斗年龄、RNG或回放哈希。thlib的hold语义及默认移动预设不变。

## 普通非符倒计时

原作 `source_reconstruction/gameplay/enemy_opcode_state.cpp:49–58` 用 ECL 513 重置阶段时钟、514 配置血量阈值与时限；`enemy_damage.cpp:49–54` 每帧将 `duration - timer_a8` 写入 Boss HUD。这条计时路径不要求符卡开启。`hud_system/update.cpp:50–64` 使用同一组公共计时动画：符卡初始 interrupt 2，普通非符为 3；不足 5 秒使用音效 11，不足 2 秒使用音效 12，对话及非战斗状态隐藏。

本作旧 Scene 已对主 Boss 非符做计时包装，但普通中 Boss 没有传递其阶段剩余时间，且固定 1,200 帧盖过内容的 25 秒配置。本次以 `src/campaign-boss-hud.ts` 的 `CampaignBossHud` 通过公共 `factories.bossHud` 接入：主非符使用 `phase.duration - phaseFrame`，普通中 Boss 使用 `midbossDuration - phaseFrame`；符卡继续接收公共 spell 已更新的剩余时间。

每个游戏 tick 只有一次公共 HUD update，计时动画、血环、秒以下数字和警告音仍由 `TouhouBossHud` 处理，没有第二套计时绘制或二次警告音。进入、对话、阶段间等待、飞离和结算明确隐藏计时，避免旧时间或 `-1` 截断成负零后显示“00”。暂停冻结阶段时钟及 HUD 更新，恢复后接续同一帧。

## 一次聚能与音效归属

道中黑雾入场后的第一段非符直接使用入场演出，不创建攻击聚能，也不再次播放54或随后补播6。之后的道中符卡、Extra开场符卡、主 Boss 非符与符卡仍共用 `_charge`：`repeatCount:1`，一次准备只生成一组聚能圈，开始时音效 54 一次，第 60 帧同一聚能释放时音效 6 一次。移除了旧主阶段连续六组聚能。被取消或结束的聚能 owner 不再补发释放音，防止声音串到下一阶段。聚能仍用公共 `TouhouBossCharge`，业务调用公共 sound 回调，不向公共视觉类塞入本作音频副作用。

原作例子 `st01bs.ecl.txt:63–68` 依次为标准 ECL 307 聚能、音效 54、等待 60 帧、释放效果与音效 6；`st04bs.ecl.txt:73–77` 等处也使用这类序列。这里的标准聚能圈是 effect 64～78 / 释放 79～92，不能与入场 `EffChargePoint3` 的 151 起始脚本混用；入场黑雾保留自己的生命周期。

音效必须查 `audio_runtime/audio_constants.cpp` 的 `effect_definitions`，先从 **effect ID** 找到对应文件，再索引 `effect_filenames`，不能把 ID 直接当文件列表序号。公共素材清单的文件列表布局也不必与还原源码完全相同；调用接口使用音效 ID：

| effect ID | 文件与用途 |
| ---: | --- |
| 30 | `se_ch00.wav` |
| 31 | `se_ch01.wav` |
| 54 | `se_ch02.wav`，标准聚能开始提示 |
| 55 | `se_ch03.wav` |
| 6 | `se_enep02.wav`，聚能释放提示 |
