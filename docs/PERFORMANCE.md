# 1.2.0 后端性能实测

游戏默认使用 V8，QuickJS 保留兼容入口。本轮测量 TS-STG `ad801fa`、七种动态符卡背景与更新后的非符、符卡短句；旧版本的采样不作为本轮结果。

## 方法与条件

在 Intel Core i7-12700H、NVIDIA GeForce RTX 3060 Laptop GPU 上运行 `node tools/measure-performance.mjs`，串行采样十个场景、两个后端，共二十次真实 GPU 运行。每个场景渲染 600 帧，舍弃前 60 帧，统计随后 540 帧。测量期间本项目的路线搜索、单元测试和原生整流程全部停止；源工程已经打开的 Rush 游戏没有被关闭，因此这不是独占整机环境。

道中额外推进 900 帧、非符额外推进 600 帧，都仅发生在预热期。测量阶段每个渲染帧严格推进一次模拟，分别覆盖道中第 961～1500 帧、非符入口第 661～1200 帧；其余入口统计第 61～600 帧。场景使用实际公共实体、原作演出、原创贴图与动态背景。测试玩家静止且无敌，不射击；魔理沙在原生渲染第 250 帧触发 Bomb。音频资源照常加载和调用，音量设为零。

下表为 `frameWorkMs`，单位毫秒，排除显示等待。P95 表示 95% 的样本不超过该耗时；弹幕 / 激光数字是原生帧中对公共弹池的采样峰值，包含出生、销毁及预热状态，不等于可见弹数或整张卡的最大密度。预热中的批量推进不会为每个内部更新采样峰值。完整 profile、GPU 查询、提交和更新耗时、截图、场景参数、源码与工具哈希保存在忽略的 `reports/performance/`。
