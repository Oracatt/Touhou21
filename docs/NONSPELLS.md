# Boss非符设计与行为验证

本次重做把七位Boss的普通攻击从同一套瞄准扇、圆环和激光循环中拆开。实现位于 [nonspells.js](../src/nonspells.js)，[patterns.js](../src/patterns.js)保留导演使用的 `updateNonspellPattern` 入口。内部风格ID用于开发和测试；非符仍是无符卡名的普通攻击，HP、时限、共享血环和切段结算继续由导演与公共thlib处理。

## 参考与节奏

只读参考本地原作脚本 `D:/AIWorkspace/Touhou20Reconstruction/scripts/recovered/ecl/st01bs.ecl.txt` 的 `Boss1`、`Boss1_at`、`Boss1_at2`，以及二面Boss对应普通攻击。参考的设计惯例是：先准备并保存瞄准角度，把出弹分成有限的短句，在短句之间等待，随后移动再等待，后续非符发展同一Boss母题。没有复制具体原作Boss图像、原作弹幕形状或ECL实现。

每轮新非符都按“移动准备 → 保存本轮瞄准地址 → 有限出弹短句 → 停止新增弹幕”进行。子弹发出后继续公共运动，没有为了制造休止而强制删除仍在飞行的弹。导演原来统一的240帧漂移已移除；每个Boss的非符拥有自己的三点移动路线，攻击期间停驻。

## 七种普通攻击

### 扉灯祈：灯笼是路标

在本轮76帧记下自机位置。88、132、176帧，两盏灯在Boss左右38像素处写出分开的灯柱，目标点从门缝两侧向外排列。灯柱使用小珠弹，交替轻偏向外侧，不做全周圆环。112和154帧的小纸弹只朝最初记下的位置发射，玩家可以先诱导再离开原位置；同一短句不会追着玩家改角度。

后续组增加灯柱层数、调整移动位置和门缝位置。Hard起198帧出现外侧慢弯灯光；Lunatic在204帧用一次新的瞄准地址补一小句。主门缝不会随新增层数缩到不可读。

### 雨巻静织：雨有整齐的邮路

76帧记地址。92、126、160、194帧从上半场按横向邮列发出竖直针雨，126和194帧的列偏移8像素，让雨不是完全重合的四次复制。Easy保留约96像素留白，Normal保留约76像素留白，留白在整轮中保持同一位置。

116、148帧的两枚信封从不同起点寄往同一个旧地址；这是可以诱导的信，不是持续追踪弹。Hard在160帧加向留白外侧倾斜的横风；Lunatic在212帧重新寄出一封回执。后续组让雨速略增、移动站位轮换，保留邮列与空地址的结构。

### 渡守澪舟：水路分两岸

76帧记下船尾波的去处。88、132、178帧，Boss两侧的起点分别写出向自己岸边弯曲的慢水流，方向向外展开，给中部水路留出穿行空间。108、126、144帧的快速船尾波全部驶向76帧记下的旧位置。

后续组增加同一水流内的层数，左右轮换靠岸位置。Hard在196帧加一层浅回流，仍限定为固定曲率和有限持续时间；Lunatic在212帧重新瞄准一次。没有玩家贴近之后突然转头的追踪命令。

### 糸守紫乃：先留缺边，再缝针

80帧记下缝针地址。100、140、184帧，上半场按竖直经线出弹，Easy省去缺边中心左右52像素内的列，Normal省去左右42像素内的列。122、160、198帧，左右针口沿同一个保存地址缝出短线，玩家可以把第一针诱到旧位置，再穿过缺边。

后续组增强经线速度并轮换站位。Hard起104帧预告一束固定角度的细线激光：角度保存一次，96帧警告后展开，没有全程跟踪；Lunatic在222帧补一次新地址。警告与经线属于不同阶段，准备期仍不发弹。

### 御影房枝：每页目录都有空栏

80帧记地址。100、140、180帧依次写三行纸札目录，第二行略错列，三行共享同一空栏。Easy空栏左右52像素，Normal左右40像素。124、164帧从两侧写出朝外弯的折页角；152、196帧在旧地址盖印，玩家不能始终停在被记下的位置，但也不必追着不停变化的瞄准点跑。

后续组增加折角层数和少量纸列速度。Hard起216帧在两侧页边盖额外印章，主要空栏继续保留；没有把方形主题换成圆环，也没有整屏无缝横墙。

### 白识言音：呼唤必须留一个回答处

80帧记地址。96、148、200帧发出声纹，第二声使用不同弹速和半格相位，圆周始终省去一个清楚的角向区间。Easy缺口半角约0.31弧度，Normal约0.245弧度，方向指向本轮固定回答处。122、172帧的回答短句发往保存地址，促使玩家在缺口里做一次小幅诱导。

后续组增加声纹音数、略提高速度，仍保留角向缺口。Hard起104帧预告偏离保存地址0.32弧度的细声线，96帧后才展开；Lunatic在222帧补一次新回答。其他Boss的普通攻击不用此声纹母题。

### 玉继未央：旧声音不会改成新地址

80帧记地址。100帧的双铃从左右起点复唱旧地址，第二声延迟到 `156 + 2 × chapter` 帧，再由204帧的第三声接上；第二声角度有左右0.075弧度的错位，仍基于同一个保存地址。122、178帧是朝外展开的慢回声线；214帧补一层偏斜回答，230帧才单独记录新地址说最后一声。

Extra十段普通攻击的第二声依次在156、158、160、162、164、166、168、170、172、174帧出现。层数只增强到两档，不无限增密；后续段用站位、双铃层数和延迟变化发展镜像主题。测试确认十段实际发射几何哈希都不同。

## 难度与阶段增强

导演的非符索引为0、2、4……，业务组号为 `chapter = floor(phaseIndex / 2)`。同Boss风格不会随组号变成另一个Boss的风格。层数增强采用 `min(2, chapter)`，避免Extra十段把非符堆到无限密度；其余区别来自站位、门缝、发射时点和该Boss特有的附加句。

| 难度 | 弹速比例 | 形状和时机 |
| --- | --- | --- |
| Easy | 0.84 | 较少灯柱/水流/声纹、较宽列间留白；旧地址短句通常一发 |
| Normal | 1.00 | 完整双侧角色与三发窄瞄准短句；仍有固定留白和长休止 |
| Hard | 1.10 | 增加各Boss自己的外侧灯光、横风、回流、预告丝线、页边印章或声线 |
| Lunatic | 1.20 | 保留旧地址诱导，同时在明显更晚的拍点允许一小句新瞄准 |
| Extra | 1.12 | 使用未央的完整镜像、偏斜回答与末音；第二回声按十段递进 |

公共激光固定宽5、96帧警告、18帧展开、42帧维持、24帧收束。非符没有改变原作激光判定修剪。普通敌弹发射携带公共出生指令，使用公共样式半径和4096的最小自机距离平方；不修改半径、不让保护帧代替安全间隙、不使用持续追踪命令。场外消亡继续由公共bounds自动处理，阶段击破消弹继续走公共清场。

## 导演与RNG所有权

`updateNonspellPattern`接受 `rng` 参数，导演传入自己的 `this.rng`。公共Player擦弹会消耗 `game.rng`，因此作者的位置/间隙变化不再每轮读公共碰撞随机流。独立嵌入时，如未传作者RNG，非符行为状态只在初始化时从 `game.rng.state` 建立一个独立的公共 `TouhouRNG`，随后保持自己的序列。没有使用 `Math.random`。

移动使用公共 `boss.motion`，不接管Enemy的实际位移/方向动画。导演在准备新阶段时归零旧Motion的flags、speed和delta，防止移动准备途中被击破后，残余速度继续带进符卡。非符击破、符卡进入、血环共享、卡间60帧等待及末卡慢消弹流程没有改动。

## 已执行的行为验证

运行：`node --test tests/nonspell.test.js`。当前四项测试通过；不把发射数量当作可玩性证明。

1. 七Boss各跑三个完整短句周期，比较真实公共Enemy运动路径与发射几何。七种路径和几何均不同；后续组仍保持同一母题。
2. 本篇21段非符分别运行Easy、Normal、Hard、Lunatic，Extra十段运行Extra，每例三个周期。每Boss的各组发射几何均不同，重复种子结果相同，改变种子会改变实际位置。停止作者发射后，所有残弹和激光在800帧内自然结束到0，未用测试清场抹掉存活证据。
3. 六面最末段非符在Easy、Normal各跑1700帧，共12例。使用真实公共弹幕、ANM、Motion和激光字段进行空间可达性搜索；自机限定在y392、每帧最多2像素横移（灵梦真实低速速度）。判定使用公共几何和实际样式半径，原作3像素自机半径额外加2像素余量，出生弹和保护弹没有被排除。路径必须在每次保存瞄准前回到原诱导位置；将该路径放回活体重新计算瞄准，实际发射哈希与搜索基线完全一致，每帧仍安全。所有路径都有实际移动，没有静止躲开瞄准弹的误判。
4. 六面Normal最末段的上述路径，各自再走真实 `TouhouGame` 和公共灵梦的 `Keys.FOCUS + LEFT/RIGHT` 输入1700帧。每帧位置与路线相等，公共自机一直保持正常状态，残机不减，无Bomb、无无敌、无Miss或死前Bomb分支。该验证包含真实擦弹及其RNG影响。
