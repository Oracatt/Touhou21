## 内容与规则

Node 测试覆盖七个关卡、34 张符卡、双自机对白与六个结局、公共符卡计时结算、共享血环转段、最终消弹与对话时序、暂停冻结、回放校验、背景透视与图集、有限道中编排，以及音轨和本地依赖清单。回放修订升为 3：旧回放文件保留，应用明确拒绝用本轮规则播放它们。

七位 Boss 的非符已从通用扇弹、圆环和激光循环拆成独立业务编排。它们分别使用双灯柱门缝、雨信邮列、双岸水流、缺边织线、目录纸栏、呼唤应答与镜像回声母题；聚能、实际攻击、移位与恢复有各自节奏。34 张符卡使用独立的短句计时表，包括开场、移位预备、发射段和恢复段。恢复段停止新的发射，但已有子弹和激光继续按公共规则运动，不能以静默清空弹幕制造安全期。

已完成的真实公共实体回归检查包含全部 34 张符卡至少两轮短句、恢复期停止新发射而保留旧轨迹、Extra 最终符卡依次推进六个母题，以及非符击破后不遗留 Boss 运动。静止弹的锁定瞄准与后续运动指令的难度速度 / 加速度倍率已纳入本轮修正及针对性断言，最终 Node 复验通过。

计时检查包含普通超时失败和耐久超时收取。本篇提供四档难度，Extra 固定使用难度四。道中保留 63 个段落、11 种运动路线和 21 种攻击，并检查全长调度、实际公共敌人动画与碰撞、有限退出、段落差异、难度差异及相同种子的重播。敌人、弹雾、子弹、激光、碰撞、武器、Bomb、消弹和结算继续由公共 thlib 所有；本作只创作角色、场景、攻击编排与对白。

攻击路线验证使用真实公共 `TouhouGame`、当前攻击函数、自机移动与有碰撞的输入回归。最终 QA 版本 2 完整重跑已经通过：`full-spells-v120.json` 为 34 / 34 张符卡、103,500 帧；`full-nonspells-v120.json` 为 31 / 31 段非符、85,260 帧；`easy-late-v120.json` 为 `s04-04` / `s05-04` / `s06-05` 三个 Easy 样本、10,500 帧。合计 **68 个完整时长见证、199,260 帧作者时长**；每项均进行两次真实输入回播，共 **398,520 次 Game 更新**，全部 `fullAuthoredDuration=true`。每帧均满足零 hit、零 Miss、零无敌、正常自机状态、实际位移与输入一致、`marginBlockedFrames=0`，两次弹幕 / 激光几何哈希一致。三份报告的业务源码、引擎锁和两个 QA 工具哈希一致，且与完成时的磁盘内容相符。

搜索使用低速灵梦，每帧速度 2、公共半径 3、额外安全边距 1.5，限定下方网格 `x=-176..176`、`y=288..432`，只允许低速停留或四向输入，不射击、不 Bomb、不暂停。预测时抑制 hit 只为观察完整轨迹；最终回播启用普通碰撞，并逐帧独立查询同样的额外边距，不改变生产判定。40 轮有限预算内，实际最多符卡 17 轮、非符 15 轮、Easy 样本 7 轮。方法与报告范围见 [ATTACK-ROUTES.md](ATTACK-ROUTES.md)。

旧工具只按实际 hit 固定安全输入前缀，会把“物理未中弹但进入规划边距”的输入冻结，误报之后没有续路；QA v2 以首次实际 hit 或首次边距接触共同决定前缀，并在预测中继续检查和回退。针对工具的五项回归已经通过；本轮没有为得到路线而修改生产弹幕、判定或边距，也没有沿用旧工具的零 hit 结果证明安全边距。找到路线只证明这些固定输入在该网格和参数下能通过，不证明所有难度均衡、没有其它封路情况，或真人初见即可通关。部分搜索时刻仅有一个可达节点，不能据此给普通玩家做难度评级；未找到路线也不自动证明弹幕无解。

## 原生完整流程

`reports/integration/acceptance-v120.json` 最终接受 **34 / 34 个成功用例、17 组 V8 / QuickJS 配对**，且与当前磁盘中的生产源码、公共库及原生程序一致。覆盖完整本篇 / Extra、关卡练习和实际应用输入，保留完整道中长度，核对中 Boss、非符与符卡、最终消弹、关卡结算及公共对象所有权；另覆盖：

- 自然击破、真实 Miss、Bomb、暂停后的录制与重播，逐个核对校验点和最终状态。
- Game Over → Continue、最高分、剩余续关次数与续关回放。
- 暂停及 Game Over 中的选项、说明、保存回放页，关闭页面后返回原菜单。
- 回放现场 Esc 暂停、恢复、退出、Shift 两倍速和损坏校验点的友好停止。
- 回放完整消费最后一帧后正常结束，不误开新局、不新建 recorder、不增加游戏次数或写成绩。
- 关闭自动保存后的手动保存，以及播放回放时不增加正式成绩或解锁。
- 取消 Extra / 关卡练习 / 符卡练习，再开始本篇；检查旧选择和种子不污染下一局。

验收分为两批：首批实际执行 34 次，32 次成功，回放输入场景的两后端用例因 QA 的 Bomb 固定按键帧恰遇自机复活入场而失败。只修正测试夹具的回放时序后，这两项各补测一次并成功。两批实际共 **36 次执行、零外部历史基线复用**；最终 34 个接受用例共记录 **562,426 次 Scene 更新、572,152 次 Application 更新**。首次两项失败的异常处理未收集完整调用计数，因此不能把上述成功用例计数声称为全部 36 次执行的精确总数。

两个批次的生产业务源码、公共库与二进制身份相同，执行期间均保持稳定，最终摘要与磁盘一致。测试夹具只改动 `replay()` 块，块外字节完全相同；专用 acceptance 记录分别保留原始批次、夹具身份和用例路径，不生成虚假的单夹具 summary。首次失败 summary 与归档均保留，补测记录见 `summary-v120-replayfix.json`。最终 acceptance SHA-256 为 `70cb4ddd2ecf2e3d5fff65764043156d10002aec00f2ad1ddfd45ebe41105249`。

自动无敌、对话和收取仅用于流程验收。游戏存档使用内存隔离，原生文件读写回环只写专用 `userdata/integration/`，测试通关和解锁不会写入正常玩家记录。完整路线证明状态转换与对象生命周期，不代替有碰撞攻击路线或真人难度评价。

## 真实画面与动态背景

`reports/backgrounds/report.json` 已完成七面道中 / 符卡共 **14 组场景、28 张原生 GPU 截图**，两后端所有配对 PNG 哈希完全相同。状态比较要求字段、整数和非数字值精确相同，仅允许相机三角运算的小数出现相对 `1e-12` 的后端舍入差异；这个容差不放宽 PNG 比较。

七张原创 RGBA 图集组成真实世界坐标中的地面、水面、墙面、建筑、树木与细节，使用透视相机和远近排序。符卡背景复用这些业务贴图，通过滚动、旋转、流动及多层图案表现七个主题，保留公共法阵和背景扭曲。暂停冻结背景时钟，背景有 48 帧进入、24 帧退出与受限的交替生命周期；资源借用由 GameArt 统一管理。背景不嵌套 scissor，场地裁剪由公共合成层负责。

## 音频与性能

17 首原创合成 BGM 的现有检查覆盖完整立体声 PCM、记谱、循环区间、哈希、峰值、循环接缝与持续音量；原生流程检查加载、重播和切换。这些结果不等同于编曲听感评价。

本轮 20 项串行原生 GPU 性能采样已完成。在 Intel Core i7-12700H、NVIDIA GeForce RTX 3060 Laptop GPU 上，十个场景分别使用两后端渲染 600 帧，舍弃前 60 帧，统计随后 540 帧的实际工作耗时；不把显示等待计入工作耗时。道中和非符额外推进只发生在预热期，正式测量每帧推进一次模拟。测试自机静止、无敌且不射击，指定场景另触发魔理沙 Bomb，音频资源正常加载但音量为零。

默认 V8 的已测道中 / 战斗窗口平均工作耗时为 **1.31～3.13 ms**，P95 为 **2.14～4.81 ms**。QuickJS 的若干密集战斗平均或 P95 仍超过 60 帧的 16.67 ms 预算。完整样本、硬件条件、峰值与超预算场景见 [PERFORMANCE.md](PERFORMANCE.md)、`reports/performance/report.json` 与 `reports/performance-v120.log`。性能报告的业务源码摘要与最终 97 场景 GPU 报告一致，二进制也为当前 `c62172…` 程序。

采样期间本项目的路线搜索、单元测试和原生整流程停止，但源工程此前已打开的 Rush 游戏没有关闭，因此这不是独占整机环境。有限窗口不能保证所有攻击、输入和硬件都有同样速度，工作耗时也不等同于显示 FPS；本记录不引用旧版本数字或据此宣称百分比性能提升。

## 依赖身份与源目录边界

`engine.lock.json` 锁定该提交的 **341 个 thlib 文件、150 个运行时 / 许可文件**和当前二进制摘要。依赖锁 / 源目录对照以及双后端原生 headless 引擎烟测已通过，记录见 `reports/engine-upgrade/summary.json`。烟测验证公共自机、武器、输入、Boss hold / resume、贴图区域和 mesh 命令，不包含 GPU 像素或真实音频听感验证。

源 `D:/AIWorkspace/TS-STG` 在本作工作中保持只读；它并非 Git 干净。锁如实记录用户已有的唯一未暂存修改 `start-spellcard-editor.cmd`：559 字节，SHA-256 `7121aa214d9f0e526f8c8188293cb07d93d6b9200600f8eab4c13e26fccd4901`，以及 `sourceModified:true`、`sourceState.gitClean:false`。该启动文件不属于原生编译 / 链接、公共库或运行时输入；同步工具只允许显式指定的这个例外，其它源改动仍会拒绝。没有向源文件写入，也没有使用 stash 或 reset 清除用户修改。

源 SDK 的 `dist/TS-STG` 仍含旧程序，不能声称该旧 SDK 与当前原生构建一致。本作 `runtime/PACKAGE.json` 使用原 SDK 模板在目标目录派生新元数据，写入当前程序摘要、提交、构建路径和模板来源；锁保留派生文本、摘要及 `derivedFor` 记录，安装器可精确重建。源 SDK 模板和旧程序都没有被修改。构建身份核对属于本地输入、对象及链接记录证据，不是可复现构建认证。

本作只依赖公共 `@ts-stg/thlib` 与 `@ts-stg/thlib/touhou`。原创图集、音乐、剧情和攻击留在本作；依赖副本、运行时、存档、报告与临时构建不进入 Git。源游戏专属业务不被转入本作的可公开业务包；代码许可、原创媒体来源和私有公共依赖的独立来源见 [RELEASE.md](RELEASE.md)。
