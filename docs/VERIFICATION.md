# 验收方法与覆盖范围

本记录对应游戏 v1.1.0 / 回放修订 2，以及 TS-STG 提交 `aa3a2349d56779f4cc3f764c944f3e9786626aa3`。本轮同步了公共 thlib 的 339 个文件与原生运行时的 150 个文件，重做七面贴图背景和道中编排。验收分开检查规则、实际原生流程、真实 GPU 画面、性能与依赖边界，不把模拟宿主测试当作原生运行。

## 内容与规则

`npm test` 的 82 项测试全部通过。覆盖七个关卡、34 张不同符卡、双自机对白与六个结局、公共符卡计时结算、共享血环转段、最终消弹与对话时序、暂停冻结、回放校验、背景透视与图集、有限道中编排，以及音轨和本地依赖清单。随后对 Extra 固定难度四的种子重播断言做针对性复验，通过；生产源码未再改变。

计时测试对全部 34 张符卡执行四组参数，包含普通超时失败和耐久超时收取。本篇提供四档难度，Extra 使用固定难度四。11 项背景测试检查贴图 UV、透明素材边界、世界坐标透视、远近绘制顺序、相机移动和借用资源的释放责任。8 项道中测试检查七面全长调度、实际公共敌人动画与碰撞、有限退出、段落差异、难度差异和相同种子的重播。

道中共有 63 个段落、11 种运动路线和 21 种攻击。新段落不修改现有 34 张 Boss / Extra 中 Boss 符卡；敌人、弹雾、子弹、激光、碰撞、武器、Bomb 和结算继续使用公共 thlib。Boss 接入新版公开的 `onDefeated`、`resumeBoss`、`removeBoss` 和聚能清理接口，关卡退场不遗留旧对象任务。

## 原生完整流程

本轮 `reports/integration/summary-v110.json` 记录 34 / 34 个用例通过、17 / 17 个 V8 / QuickJS 配对结果一致。全部用例在当前源码及更新后的真实 `runtime/ts-stg.exe` 上重新执行，保留基线用例为零。共推进 560,848 次 Scene 更新和 570,574 次 Application 更新；验证期间游戏源码、公共库和只读依赖源均未改变。

八条路线分别为灵梦 Easy / Normal / Hard / Lunatic 本篇、魔理沙 Normal 本篇、双自机 Extra 和三面练习。它们保留完整道中长度，检查六面推进、中 Boss、非符与符卡、最终消弹、关卡结算、Extra 与练习完成，以及公共对象所有权。灵梦每条本篇推进 44,130 帧，魔理沙本篇 44,267 帧；双自机 Extra 分别推进 16,692 / 16,727 帧。

另外九种应用输入场景使用实际按键边沿与等待时序，覆盖：

- 自然击破、真实 Miss、Bomb、暂停后的录制与重播，逐个核对校验点和最终状态。
- Game Over → Continue、最高分、剩余续关次数与续关回放。
- 暂停及 Game Over 中的选项、说明、保存回放页，关闭页面后返回原菜单。
- 回放现场 Esc 暂停、恢复、退出、Shift 两倍速和损坏校验点的友好停止。
- 退出 / 重开录制的回放完整消费最后一帧后正常结束，不误开新局、不新建 recorder、不增加游戏次数或写成绩。
- 关闭自动保存后的手动保存，以及播放回放时不增加正式成绩或解锁。
- 取消 Extra / 关卡练习 / 符卡练习，再开始本篇；进入后退出再开始。检查旧选择和种子不污染下一局。

自动无敌、对话和收取仅用于验收。游戏存档在测试中使用内存隔离，原生文件读写回环仅写专用 `userdata/integration/`，不会将测试通关和解锁写入正常玩家记录。运行器本轮使用两个 worker，每个子进程上限 30 分钟。

早期 v1.0 的报告仍作为历史记录保留，本轮未复用它们。新报告记录具体源文件、验证脚本、公共库、引擎哈希及实际更新次数。道中变化使回放修订升为 2：旧回放文件保留，但应用明确拒绝用新规则播放它们。

## 真实画面

`reports/visual/report.json` 记录 76 个应用场景、两种后端各一张，共 152 张原生 GPU 截图。包含标题页面、难度与自机选择、场景切换、七面道中、黑雾、双自机对话、全部 34 张符卡、耐久、符卡立绘、两种 Bomb、暂停、关卡结算、过渡、结局、职员表与结果。75 组配对 PNG 完全相同；选项页因有意显示不同后端名称允许像素差异。移除后端名称字段后，配对应用状态一致。

`reports/backgrounds/report.json` 另记录七面道中 / 符卡共 14 组场景、28 张截图。所有配对 PNG 哈希完全相同。状态比较要求字段、整数和非数字值精确相同，仅允许相机三角运算的小数出现相对 `1e-12` 的后端舍入差异。这个容差不放宽 PNG 比较。

七张原创 RGBA 图集组成世界坐标中的地面、水面、墙面、建筑、树木与细节，使用真实透视和多层景深。移除原先的箱体、圆柱与纯白材质，修复地面 UV 接缝、透明边距引起的比例失真、桥脚被水面覆盖和丝带遮盖过强。道中最多 432 个顶点 / 7 次 mesh 提交，符卡环境最多 148 个顶点 / 1 次提交。场地裁剪由公共合成层负责，背景不嵌套 scissor。

本轮人工查看了七面新道中的应用截图，以及多张独立背景和符卡环境截图；另一次只读复核查看了二 / 四 / 五 / 七面道中和六面符卡，未发现明显黑边、邻格串图、HUD 遮挡或场地裁剪问题。自动检查仍覆盖全部 34 张符卡和六条结局路径。原作 STD / ANM 资料只用于参考贴图、相机和层次设计，本轮没有运行原作程序做逐像素对照。

## 音频、性能与依赖

17 首原创合成 BGM 保持不变，现有测试检查完整立体声 PCM、记谱、循环区间、哈希、峰值、循环接缝和持续音量。原生流程检查加载与切换；这些结果不等同于编曲听感评价。

本轮串行执行八个场景 × 两个后端的真实 GPU 性能采样，每个场景预热 60 帧后测量 540 帧；道中额外推进只发生在预热阶段。默认 V8 的已测道中和战斗平均工作耗时为 1.23～3.29 ms。QuickJS 在较密集战斗中仍会超过每帧 16.67 ms 的预算。硬件、样本、范围与逐项数据见 [PERFORMANCE.md](PERFORMANCE.md)，不推定所有机器和输入的帧率。

依赖锁及源目录对照通过，源 TS-STG 保持 Git 干净。安装器的 10 项真实恢复 / 幂等 / 拒绝覆盖 / 路径检查通过；依赖与同步保护的 8 项测试检查本地修改、存档保留和路径边界。新增原生引擎烟测在 V8 / QuickJS 中各推进 120 帧双自机实际玩法，验证公共武器、输入、Boss hold / resume、贴图区域和 mesh 命令，配对哈希为 `c533ba34`。

游戏业务只依赖公共 `@ts-stg/thlib` 与 `@ts-stg/thlib/touhou`。原创图集和道中内容留在本作，依赖副本、运行时、存档、报告和临时构建均不进入 Git。同步工具默认 dry-run，验证目标提交、旧依赖未修改和源构建身份后才替换本地副本，并保存可恢复备份。
