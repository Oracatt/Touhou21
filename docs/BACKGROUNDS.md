# 道中三维与抽象符卡背景

背景使用游戏自己的 [src/background.js](../src/background.js)、[src/background-art.js](../src/background-art.js) 与 [src/spell-background.js](../src/spell-background.js)。道中通过 TS-STG 公共 DrawList.mesh3d 绘制贴图构建的实时三维空间；符卡切换为七位 Boss 各自独立的全幅抽象纹样。稳态符卡不提交道中景物或三维符卡舞台，进退期间才与道路画面交叉淡化。

## 原作构建方法与本作边界

只读参考为 Touhou20Reconstruction 的 scripts/recovered/std/st01.std.txt、st05.std.txt，scripts/recovered/anm/st01wl.anm.txt，以及 source_reconstruction/stage_background 下的相机、雾、投影与脚本模块。STD 的 ENTRY/QUAD 把带不同尺寸、坐标和动画的面片组合为对象，再在场景中放置多个 INSTANCE；相机位置、方向、视场角与雾随时间更新。st01 的地面与分层植被、st05 的重复面组及镜头插值提供了设计依据。

本作借鉴这种“绘制素材组成空间、镜头穿行其中”的方法，未复制锦上京的背景素材、STD 时间表或 ANM。新图集均由内置 image_gen 生成，复制时保持文件字节和透明通道原样。没有使用 Python 绘画、抠图、缩放或重绘；离线读取 alpha 只用于记录 UV 范围。全部七张图的最终尺寸为 1254×1254，尽管生成提示要求 1024×1024，程序按实际尺寸采样。

## 素材与透视

每面独立图集放在 assets/scenery/stage01-atlas.png 至 stage07-atlas.png。每图四格分别是俯视连续地面、标志建筑、侧景和饰物。三格景物保留真实 alpha，地面格不透明。background-art.js 保存逐格实测轮廓范围，并保留至少两像素边缘：运行时直接选取 atlas UV，不生成裁切图片，不把透明边距误作物体的高度。

顶点始终为世界中的 [x,y,z,u,v,color]。横置地面、水面与云层、竖置景物、朝向走廊的书架墙拥有不同朝向和距离。JS 只建立观察、透视和视窗 MVP；GPU 接收原始 Clip W 并执行透视正确的 UV 插值与齐次近远裁剪。没有把三维位置先投影成屏幕精灵，也没有用一张整景画作替代三维前景。

assets/art/stage01.png 至 stage07.png 仍以低亮度提供远处天空、山林或建筑轮廓。移除此远景层，地面、河水、门、树、船、书架、名牌和相机产生的大小变化与视差仍然存在。

## 动态符卡背景

[src/spell-background.js](../src/spell-background.js) 只负责本作的视觉内容。只读参考是 TS-STG 的 games/rushboss/src/stage-artwork.js：默认竖屏 Demo 在 priority 11 调用 drawSpell，各张卡独立保存 age、scroll、alpha 与 leaving，底纹和另一层流纹按不同方向采样，结束后继续移动并淡出。这里借鉴其分层与生命周期设计，不复制 Rush 的图像、私有代码、魔法阵或扭曲效果。

原作抽象纹样的只读依据还包括 Touhou20Reconstruction 的 scripts/recovered/anm/st01enm.anm.txt:1068–1137 和 st03enm.anm.txt:1008–1085：底图与大尺度 pattern 分层，使用不同的 UV 位移、相反旋转以及减色/加色控制亮度。本作借鉴其满幅纹样、独立层速与低对比原则，不使用原作纹理，也不宣称逐帧复现其 ANM 或混合参数。

每位 Boss 现在使用 assets/spells/<bossId>.png 的独立、不透明纹样；七张实际尺寸均为 1254×1254。运行时通过 GameArt.load 读取真实尺寸，不把分辨率写死。每张卡由两层完整纹理组成：主层在进入完成后以不透明 alpha 覆盖整个场地，次层以约 0.075–0.125 的低透明度柔和叠合。两层都有独立旋转、偏移、缩放周期；着色压低亮度但保留图案的中间调。不同 Boss 的方向、轴向与速度并不共用同一套运动参数。

| Boss | 主纹样运动 | 次纹样运动 |
| --- | --- | --- |
| 扉灯祈 | 花结、封印顺时针旋转并缓慢呼吸 | 较快反向旋转，横向偏移 |
| 雨巻静织 | 小倾角、主要纵向流动与雨墨波动 | 不同纵向周期、轻微旋转与波动 |
| 渡守澪舟 | 水纹轻摆、横向偏移与连续涟漪 | 反向慢旋转，纵向偏移与另一相位涟漪 |
| 糸守紫乃 | 斜置织纹横向穿行，纹理弯动 | 反向倾角、纵向偏移与错相金线 |
| 御影房枝 | 印纹慢转并纵向偏移 | 较快反向旋转，以另一尺度错开印格 |
| 白识言音 | 云莲、曼荼罗缓慢逆转与伸缩 | 双倍速度顺转，另一伸缩周期 |
| 玉继未央 | 镜羽逆转、轻摆与波动 | 水平镜像后顺转，反向漂移与错相波动 |

Extra 的中 Boss 是房枝，纹样按实际 bossId 选择 fusae.png，不能按第七面误用 mio.png。所有纹理借用 GameArt 的缓存，背景 owner 不创建额外纹理或渲染目标，不加载锦上京、Rush 的符卡专属资源。

两层均只采完整 UV [0,0]–[1,1]，使用 bilinear/clamp；水平镜像只交换完整图的 U 方向。图像面片按场地对角线、位移上界和波动上界预留足够尺寸，因此旋转、偏移和缩放期间始终覆盖 x=48..624、y=24..696。没有小图块重复、棋盘接缝或图集邻格。雨墨、水纹、织锦、镜羽采用每层 6×6 格、49 个共享顶点的轻微面片弯动；它们仅扭动绘制好的图案，不生成程序纹样或三维景物，相邻格不会张开裂缝。

一次符卡开始后，背景用 48 个模拟帧进入；结束后以结束时的实际透明度继续运动，并在 24 帧内退出。下一张可以在旧背景淡出时开始，两张独立保存时钟与透明度，最多保留两张。换关和销毁清理全部视觉状态。背景不会作为 TouhouSpell.background 传入：公共符卡 finish 会立即销毁该 ANM，并在不同的公共绘制路径提交它，这会破坏当前淡出与背景捕获边界。

StageBackground.update 在成功的游戏帧更新后读取 spell.active、符卡标识与 context.boss.bossId；暂停时既不更新背景时间，也不处理生命周期。draw 只读取该帧，即使暂停菜单重复渲染、截图多次采样，纹样、道路相机和退出透明度都保持不动。第一次直接渲染已开始的练习卡可以做一次初始化同步；此后独立调用方必须 update。相位由注入 seed 和稳定符卡标识计算，未使用 Date.now、Math.random 或游戏 RNG。任意一张可见卡达到不透明时，道路 mesh3d 与远景完全不提交；结束后正常恢复道路。

## 图层、雾与性能

公共 mesh3d 不开启深度缓冲。本作使用受约束的场景拓扑：云在石道下、地面在站立面片下，各组内部按相机前向从远到近排序。同一图集允许一个批次内正确排列地面与透明景物；不会把远处灯或信纸另作为最上层屏幕覆盖物。不能仅按面中心深度把地面放到桥脚前面，因此层次首先服从这种明确的上下关系。道路分段再由远到近提交，避免互相穿插的面组。

地面拆成短透视条带，相邻条带共享完全相同的接缝 UV；每个区段以完整的一格地面从近端 v=1 到远端 v=0 连续采样。世界原点跟随道路段重置，使长时间运行仍保持稳定的小矩阵数值。近裁剪交给 GPU，不做接近零 Z 的屏幕坐标除法。

静态道路顶点、UV、色彩以及有限的九档距离衰减缓存不在每帧重建。道路有三种交替区段，普通场景固定七次 mesh3d 提交、最多 432 个世界顶点。稳态符卡只有两次屏幕纹理 mesh 提交：花结、印纹、云莲为每卡 8 顶点，其余四种波动纹样为每卡 98 顶点。两张进退交叠并恢复道路的上限是 11 次提交、628 顶点；不再重建三维符卡布景。图集、纹样首次由 GameArt 加载，生命周期和肖像一致；StageBackground.destroy 只丢弃 CPU 场景与动态卡状态，不抢先卸载共享材质。

距离衰减、压低的远景、轻微暗色覆盖控制亮度。全部动态内容位于业务背景捕获层，公共 Boss 双圈、14/15 背景扭曲随后基于已完成的捕获画面合成；弹幕、题名、计时和 HUD 保持原公共优先级。背景不开启或结束 scissor，也不持有独立渲染目标；调用方的 thlib 合成器负责 x=48..624、y=24..696 的场地裁剪，右侧 HUD 位于此三维视窗外。每个混合范围均关闭，不把动态纹理画到 UI 或弹幕上。

## 调用与验证

StageBackground({art,seed}) 接受 GameArt 与可选的确定种子；setStage(stage) 接受 1..7 或关卡对象；update(game,{clock,bossId}) 的默认值是 game.frame 和 game.context.boss.bossId，必须在成功的未暂停模拟更新后调用；draw(draw,game,{stage,clock}) 使用现有队列采样该视觉帧。game.spell.active 选择符卡状态。接口的旧参数仍兼容，动态效果的推进通过新增 update 显式完成。

tests/background.test.js 当前 17 项通过，覆盖保留的道路矩阵、Clip W、近远平面、场地映射、七种道路空间、独立抽象纹理运动、稳定 seed/clock、重复渲染与暂停冻结、48/24 帧进入退出、实际中 Boss 身份、两卡预算、道中 UV 与地面接缝、书架墙朝向、静态顶点缓存、长时间坐标及共享材质生命周期。符卡回归使用 mock GameArt，不依赖新 PNG 是否已经到盘：1024、1254、1536 方图及 1536×1024 非方图均验证旋转、漂移、波动后的全场覆盖与完整 UV；还检查稳态道路和远景没有任何绘制提交、四种纹样有真实弯动且共享接缝顶点。七种主题在相距 120 帧的样本中验证 mesh 变化，不依赖三维相机 MVP。

tools/verify-background.mjs 可串行捕获七面道中与七个符卡环境，并比较 V8 / QuickJS 的状态和 PNG。本轮已完成后台原生截图及主游戏合成后的弹幕可读性检查，具体证据见下文；后端一致本身不能说明审美与原作完全一致。此前白色材质几何版本的截图和性能结果不能用于此次重做的验收。

此前“场景图集 + 三维符卡舞台”动态版本的背景专用原生检查曾运行七面 × 道中/符卡 × V8/QuickJS，每个样本 240 帧，共 28 次短运行，14 对 PNG 哈希严格相同；其实际样本最多 11 次提交、1,108 顶点。当时检查了十四种画面及灯位、丝绸、云铃、倒铃的跨帧变化，报告保留于被 Git 忽略的 reports/backgrounds/report.json、motion-comparison.json 与 reports/backgrounds-frame120/。这是旧版历史记录，不能用于本次七张抽象符卡纹样的画面验收。

当前抽象纹样已完成 42 次孤立背景 GPU 检查：七套符卡在 120 / 240 帧各运行 V8 / QuickJS，七面道中在 240 帧运行两后端。每对 PNG 严格相同，七套纹理的两个时间点均有变化；七张符卡图已人工查看。报告在 reports/backgrounds/spell-patterns-120/、spell-patterns-240/ 和后者的 motion-comparison.json。随后在升级后的公共依赖下，七位 Boss 的真实弹幕各采两个时刻，共 28 次 GPU 检查通过，14 对状态 / PNG 严格相同；已逐张查看 14 张 V8 图，确认满幅图案、弹幕 / 激光、符卡名、双圈及扭曲层次。报告在 reports/visual/spell-patterns/selected-report.json 与 visual-review.json。这些指定样本的检查不构成全战役、性能或所有符卡可玩性验收。

道路图集的完整生成提示与工具说明保存于 [SCENERY-PROMPTS.json](SCENERY-PROMPTS.json)，来源与 SHA-256 保存于 [SCENERY-SOURCES.json](SCENERY-SOURCES.json)。新增符卡纹样的生成提示与来源分别保存于 [SPELL-PATTERN-PROMPTS.json](SPELL-PATTERN-PROMPTS.json)、[SPELL-PATTERN-SOURCES.json](SPELL-PATTERN-SOURCES.json)。两组资源均属于本作业务内容，随本作走独立素材与同人发布说明，不进入 thlib。
