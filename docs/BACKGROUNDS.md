# 道中三维与抽象符卡背景

背景使用游戏自己的 [src/background.ts](../src/background.ts)、[src/background-art.ts](../src/background-art.ts)、[src/stage-camera.ts](../src/stage-camera.ts)、[src/stage-atmosphere.ts](../src/stage-atmosphere.ts) 与 [src/spell-background.ts](../src/spell-background.ts)。道中通过 TS-STG 公共 DrawList.mesh3d 绘制贴图构建的实时三维空间，环境层把粒子放进同一空间，用道路镜头投影；符卡切换为七位 Boss 各自独立的全幅抽象纹样。稳态符卡不提交道中景物或环境粒子，进退期间才与道路画面交叉淡化。

## 道中环境动态

保留七关现有地面、建筑和远景贴图。环境层是本作的关卡设计，位于道路几何之后、符卡图片之前，和道路一起进入公共背景捕获、扭曲与裁剪；敌人、弹幕、自机、文字及 HUD 的公共层序不变。

| 关卡 | 环境动态 |
| --- | --- |
| 灯笼坂 | 风中翻转飘落的枫叶、萤火、两侧灯笼上的暖色光晕 |
| 湿墨竹林 | 带透视的细雨、落在石路上的雨滴涟漪 |
| 无名渡口 | 河面碎光、错峰扩散的水环、贴水低雾；拱桥后方不绘制 |
| 记忆织庭 | 翻转飘落的梅瓣、闪烁的金尘 |
| 归名书库 | 书架间的浮尘、缓慢翻落的纸片；门框后方不绘制 |
| 无名之庭 | 从云下升起的光尘、两侧云气、随钟声明灭的钟光 |
| 倒铃回廊 | 缓慢上升并翻面的镜片、逆向上升的细雨、镜面涟漪 |

粒子是道路三维空间里的点，不是在屏幕上自行漂移的贴图。每个粒子有世界坐标，和道路共用 [src/stage-camera.ts](../src/stage-camera.ts) 中的 `cameraForStage` 与投影矩阵，在 CPU 上投影成屏幕位置和尺寸，再以 2D mesh 提交。因此近处的叶片更大、移动更快，远处的更小、更淡，并随镜头横移和俯仰产生视差。粒子按世界深度分成循环的格子，越过镜头后在远端重新出现；下落、上升和翻转由模拟时钟的周期驱动。灯笼和钟的光晕按景物的实际位置计算，随景物一起后退。三面拱桥和五面门框是挡在路上的实体，位于它们后方的粒子不绘制。

上一版看起来怪异，主要因为公共圆环贴图让每颗粒子都是空心的，水纹是一像素宽的细环，粒子的屏幕漂移与镜头运动无关，部分粒子直接裁自景物贴图，并在场地边缘被夹住。现在柔光、雨丝、涟漪和纸片都只取 `boss.aura-ring` 中心一个不透明白色纹素，形状和柔边全部由顶点 alpha 构成；叶片和花瓣使用公共 `charge.leaf`，翻面时压窄并调暗。两者都从公共 `spell-common` 资源包通过公开 `SpriteAtlas` 的命名 sprite 读取，保留该包已有来源和许可。不再借用 scenery atlas 的 detail 区域，不新增或重画贴图，也不复制商用原作的专属关卡背景。纹理由 `GameArt` 缓存并释放，环境 owner 只借用句柄。粒子数量、配色、轨迹和布局均是本作选择。

每个粒子槽的随机量由 `seed + stage + index` 与循环轮次的整数哈希稳定生成。位置、翻转、扩散和透明度完全由背景模拟时钟采样；循环端点先淡至透明，暂停冻结，重复绘制和换关返回没有累积状态。不使用战斗 RNG、`Math.random`、任务或实体池，不参与碰撞、分数及回放状态，因此内容/回放修订保持 19。

环境几何按纹理和混合方式合批。被遮挡或离开场地的粒子保留为透明顶点，所以每关的顶点布局固定。预算是每关至多 4 次 mesh、600 个顶点，目前实际为 1–2 次、最多 560 个顶点。加色粒子的 alpha 不超过 122/255，普通混合不超过 170/255，不会盖过弹幕。`stats.atmosphere.particles` 是每帧提交的粒子槽数，`visible` 是当帧有透明度的数量；过桥、过门时 `visible` 可以短暂为 0。混合后保留捕获目标 alpha，并立即恢复混合状态。完整不透明的符卡底图出现时，整个道中环境层停止提交。

## 原作构建方法与本作边界

只读参考为 Touhou20Reconstruction 的 scripts/recovered/std/st01.std.txt、st05.std.txt，scripts/recovered/anm/st01wl.anm.txt，以及 source_reconstruction/stage_background 下的相机、雾、投影与脚本模块。STD 的 ENTRY/QUAD 把带不同尺寸、坐标和动画的面片组合为对象，再在场景中放置多个 INSTANCE；相机位置、方向、视场角与雾随时间更新。st01 的地面与分层植被、st05 的重复面组及镜头插值提供了设计依据。

本作借鉴这种“绘制素材组成空间、镜头穿行其中”的方法，未复制原作的背景素材、STD 时间表或 ANM。新图集均由内置 image_gen 生成，复制时保持文件字节和透明通道原样。没有使用 Python 绘画、抠图、缩放或重绘；离线读取 alpha 只用于记录 UV 范围。全部七张图的最终尺寸为 1254×1254，尽管生成提示要求 1024×1024，程序按实际尺寸采样。

## 素材与透视

每面独立图集放在 assets/scenery/stage01-atlas.png 至 stage07-atlas.png。每图四格分别是俯视连续地面、标志建筑、侧景和饰物。三格景物保留真实 alpha，地面格不透明。background-art.js 保存逐格实测轮廓范围，并保留至少两像素边缘：运行时直接选取 atlas UV，不生成裁切图片，不把透明边距误作物体的高度。

顶点始终为世界中的 [x,y,z,u,v,color]。横置地面、水面与云层、竖置景物、朝向走廊的书架墙拥有不同朝向和距离。JS 只建立观察、透视和视窗 MVP；GPU 接收原始 Clip W 并执行透视正确的 UV 插值与齐次近远裁剪。没有把三维位置先投影成屏幕精灵，也没有用一张整景画作替代三维前景。

assets/art/stage01.png 至 stage07.png 仍以低亮度提供远处天空、山林或建筑轮廓。移除此远景层，地面、河水、门、树、船、书架、名牌和相机产生的大小变化与视差仍然存在。

## 动态符卡背景

[src/spell-background.ts](../src/spell-background.ts) 只负责本作的视觉内容。符卡底纹在 priority 11 调用 drawSpell，各张卡独立保存 age、scroll、alpha 与 leaving，底纹和另一层流纹按不同方向采样，结束后继续移动并淡出。这里采用这种分层与生命周期设计，不复制任何参考工程的图像、私有代码、魔法阵或扭曲效果。

原作抽象纹样的只读依据还包括 Touhou20Reconstruction 的 scripts/recovered/anm/st01enm.anm.txt:1068–1137 和 st03enm.anm.txt:1008–1085：底图与独立大尺度 pattern 分层，使用不同的 UV 位移、相反旋转以及减色/加色控制亮度。七面原作入口使用 60 帧淡入；例如一面是底图、加色纹样、减色纹样，三面是底图和以不同角速度反转的两层纹样。本作采用两张独立图和三层合成，按自己的主题调节透明度及加减色，不使用原作纹理，也不宣称逐参数复现其 ANM。

每位 Boss 使用两张独立图：assets/spells/<bossId>-base.png 是新绘制、不透明的低频流墨、云气或纸墨底图；assets/spells/<bossId>.png 保留原有抽象纹样，七张纹样的实际尺寸均为 1254×1254。底图与纹样不是同图副本，运行时分别通过 GameArt.load 读取真实尺寸和纹理句柄，不把分辨率写死。每张卡依次绘制底图、主纹样、反向弱纹样三层。底图 alpha 为 1，在进入完成后覆盖整个场地；主纹样 alpha 为 0.42–0.50，弱纹样为 0.075–0.105。每层显式声明自己的纹理、混合模式、透明度、着色和运动，不再按层序硬编码第二层透明度或把一张纹样兼作底图。

底图以较慢速度偏移、旋转和伸缩。主纹样采用普通 alpha 混合，保留图案中间调；水纹、织锦和印纹的反向弱层采用低强度减色，其余采用低强度加色。各混合范围单独关闭，并保留已捕获画面的 alpha：颜色使用对应的 srcAlpha 混合，alpha 通道使用 zero/one/add。公共 DrawList 的减色方程名是 reverseSubtract。不同 Boss 的方向、轴向、速度和加减色并不共用同一套演出参数。

| --- | --- | --- |
| 扉灯祈 | 花结、封印顺时针旋转并缓慢呼吸 | 较快反向旋转、横向偏移、低强度加色 |
| 雨巻静织 | 小倾角、主要纵向流动与雨墨波动 | 不同纵向周期、轻微旋转与波动、低强度加色 |

| 糸守紫乃 | 斜置织纹横向穿行，纹理弯动 | 反向倾角、纵向偏移、错相金线、低强度减色 |

Extra 的中 Boss 是房枝，两张图按实际 bossId 选择 fusae-base.png 与 fusae.png，不能按第七面误用未央的两张图。所有纹理借用 GameArt 的缓存，背景 owner 不创建额外纹理或渲染目标；同卡两层纹样共享自己的 pattern 句柄，底图使用另一句柄，不加载原作或其他参考工程的符卡专属资源。

三层均只采完整 UV [0,0]–[1,1]，使用 bilinear/clamp；水平镜像只交换完整图的 U 方向。每层按自己的实际尺寸、场地对角线、位移上界和波动上界预留足够尺寸，因此两张图即使宽高不同，旋转、偏移和缩放期间仍覆盖 x=48..624、y=24..696。没有小图块重复、棋盘接缝或图集邻格。雨墨、水纹、织锦、云莲、镜羽的两层 pattern 采用各 6×6 格、49 个共享顶点的轻微面片弯动；底图保持 4 个顶点。它们仅扭动绘制好的图案，不生成程序纹样或三维景物，相邻格不会张开裂缝。

一次符卡开始后，背景用参考原作入口的 60 个模拟帧进入；结束后以结束时的实际透明度继续运动，并在 24 帧内退出。24 帧淡出是本作的演出选择，不是原作退出时间的逐帧声明。各图层自身透明度乘以同一卡的进退包络；下一张可以在旧背景淡出时开始，两张独立保存时钟与透明度，最多保留两张。换关和销毁清理全部视觉状态。背景不会作为 TouhouSpell.background 传入：公共符卡 finish 会立即销毁该 ANM，并在不同的公共绘制路径提交它，这会破坏当前淡出与背景捕获边界。

StageBackground.update 在成功的游戏帧更新后读取 spell.active、符卡标识与 context.boss.bossId；暂停时既不更新背景时间，也不处理生命周期。draw 只读取该帧，即使暂停菜单重复渲染、截图多次采样，纹样、道路相机和退出透明度都保持不动。第一次直接渲染已开始的练习卡可以做一次初始化同步；此后独立调用方必须 update。相位由注入 seed 和稳定符卡标识计算，未使用 Date.now、Math.random 或游戏 RNG。只有可见卡的 base 层达到不透明时，道路 mesh3d 与远景才完全不提交，pattern 的透明度和混合模式不能决定这项覆盖；结束后正常恢复道路。这次变化只涉及视觉时钟，不改战斗、回放或游戏 revision。

## 叠加层的灵动感

原作符卡背景上叠的那一层不是单纯慢转：它在旋转、缩放、位移之外还有明暗的呼吸。本作的叠加层（`pattern`）与回声层（`echo`）在 `src/background-art.js` 里按“速度倍率”放大了原有的慢几何：旋转约 2.2 / 2.6 倍，漂移速度约 2.4 / 2.8 倍，缩放呼吸约 3 倍（周期约 6 到 10 秒），底图仍保持缓慢。两层的所有顶点共享同一张 7×7 网格，除了原有的横纵波，还多了一圈从图中心向外传播的涟漪（`ripple`，推进速度由 `flow` 决定），所以图案会像水墨里的波纹一样起伏，不是整张图平移。

`spellLayerOpacity(layer,card)` 让两层的不透明度随卡片年龄和种子起伏：叠加层在 `(1-pulse)·opacity` 与 `opacity` 之间呼吸（`pulse` 0.34），加色 / 减色的回声层起伏更大（`pulse` 0.8，上限提到约 0.14 到 0.18），并且与叠加层相差半个周期，亮度在两层之间交替。它是卡片年龄的纯函数，暂停时冻结，重绘仍是幂等的；底图保持完全不透明，所以“底图完全覆盖道路”的规则不变。UV、整图采样和边缘覆盖的约束都没变。

## 图层、雾与性能

公共 mesh3d 不开启深度缓冲。本作使用受约束的场景拓扑：云在石道下、地面在站立面片下，各组内部按相机前向从远到近排序。同一图集允许一个批次内正确排列地面与透明景物；不会把远处灯或信纸另作为最上层屏幕覆盖物。不能仅按面中心深度把地面放到桥脚前面，因此层次首先服从这种明确的上下关系。道路分段再由远到近提交，避免互相穿插的面组。

地面拆成短透视条带，相邻条带共享完全相同的接缝 UV；每个区段以完整的一格地面从近端 v=1 到远端 v=0 连续采样。世界原点跟随道路段重置，使长时间运行仍保持稳定的小矩阵数值。近裁剪交给 GPU，不做接近零 Z 的屏幕坐标除法。

静态道路顶点、UV、色彩以及有限的九档距离衰减缓存不在每帧重建。道路有三种交替区段，普通场景固定七次 mesh3d 提交、最多 432 个世界顶点，环境层额外预算为 4 次 mesh、600 顶点。稳态符卡只有三次屏幕纹理 mesh 提交：花结、印纹为每卡 12 顶点，其余五种波动纹样为每卡 102 顶点。两张进退交叠并恢复道路与环境的上限是 17 次提交、1,236 顶点。图集、公共粒子材质、底图及纹样首次由 GameArt 加载，生命周期和肖像一致；StageBackground.destroy 只丢弃 CPU 场景与动态状态，不抢先卸载共享材质。

距离衰减、压低的远景、轻微暗色覆盖控制亮度。全部动态内容位于业务背景捕获层，公共 Boss 双圈、14/15 背景扭曲随后基于已完成的捕获画面合成；弹幕、题名、计时和 HUD 保持原公共优先级。背景不开启或结束 scissor，也不持有独立渲染目标；调用方的 thlib 合成器负责 x=48..624、y=24..696 的场地裁剪，右侧 HUD 位于此三维视窗外。每个混合范围均关闭，不把动态纹理画到 UI 或弹幕上。

## 调用与验证

StageBackground({art,seed}) 接受 GameArt 与可选的确定种子；setStage(stage) 接受 1..7 或关卡对象；update(game,{clock,bossId}) 的默认值是 game.frame 和 game.context.boss.bossId，必须在成功的未暂停模拟更新后调用；draw(draw,game,{stage,clock}) 使用现有队列采样该视觉帧。game.spell.active 选择符卡状态。接口的旧参数仍兼容，动态效果的推进通过新增 update 显式完成。

tests/background.test.js 当前 20 项通过，覆盖保留的道路矩阵、Clip W、近远平面、场地映射、七种道路空间、独立抽象纹理运动、稳定 seed/clock、重复渲染与暂停冻结、60/24 帧进入退出、实际中 Boss 身份、两卡预算、道中 UV 与地面接缝、书架墙朝向、静态顶点缓存、长时间坐标及共享材质生命周期。符卡回归使用 mock GameArt，不依赖新 PNG 是否已经到盘：底图与 pattern 返回不同的句柄，逐层核验纹理顺序、独立 blend/opacity/tint、alpha 通道保留以及共享退场包络；1024、1254、1536 方图和两图各自不同方向的非方图均验证旋转、漂移、波动后的全场覆盖与完整 UV。还检查稳态道路和远景没有任何绘制提交、五种纹样有真实弯动且共享接缝顶点。七种主题在相距 120 帧的样本中验证 mesh 变化，不依赖三维相机 MVP。

tools/verify-background.mjs 可串行捕获七面道中与七个符卡环境，并比较 V8 / QuickJS 的状态和 PNG。两图三层版本已完成七 Boss × 实际时钟 120 / 240 × V8 / QuickJS 共 28 次 GPU 检查，实际两种纹理 ID、独立文件哈希、三层顺序及混合均通过，PNG 后端逐组相同，七组跨帧图像均变化；120 帧七张 V8 图逐张检查。工具使用 --clock-start 0，旧默认起始时钟为 480。随后七个实际符卡战斗与一次符卡入场共 16 次 GPU 检查通过，8 张 V8 图已逐张查看；弹幕、题名、双圈和扭曲层次正常。报告在 reports/backgrounds/spell-layers-120/、spell-layers-240/ 与 reports/visual/spell-layers/，细节见 VERIFICATION.md。此前白色材质几何版本的截图和性能结果也不能用于此次重做的验收。

此前“场景图集 + 三维符卡舞台”动态版本的背景专用原生检查曾运行七面 × 道中/符卡 × V8/QuickJS，每个样本 240 帧，共 28 次短运行，14 对 PNG 哈希严格相同；其实际样本最多 11 次提交、1,108 顶点。当时检查了十四种画面及灯位、丝绸、云铃、倒铃的跨帧变化，报告保留于被 Git 忽略的 reports/backgrounds/report.json、motion-comparison.json 与 reports/backgrounds-frame120/。这是旧版历史记录，不能用于本次七张抽象符卡纹样的画面验收。

前一轮“一张抽象纹样双层合成”完成过 42 次孤立背景 GPU 检查：七套符卡分别运行 120 / 240 个原生帧，七面道中运行 240 帧，均覆盖两后端。旧夹具从背景时钟 480 开始，实际采样时钟为 600 / 720，不是符卡出生后 120 / 240 帧。每对 PNG 严格相同，七套纹理的两个时间点均有变化；七张符卡图已人工查看。报告保留在 reports/backgrounds/spell-patterns-120/、spell-patterns-240/ 和后者的 motion-comparison.json。随后在当时的公共依赖下，七位 Boss 的真实弹幕各采两个时刻，共 28 次 GPU 检查通过，14 对状态 / PNG 严格相同；当时逐张查看 14 张 V8 图，报告在 reports/visual/spell-patterns/selected-report.json 与 visual-review.json。这些是历史样本，不能证明本次两张独立图、三层合成的画面通过，也不构成全战役、性能或所有符卡可玩性验收。
