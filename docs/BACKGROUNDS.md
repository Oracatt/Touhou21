# 贴图构建的实时三维背景

背景使用游戏自己的 [src/background.js](../src/background.js) 与 [src/background-art.js](../src/background-art.js)，通过 TS-STG 公共 DrawList.mesh3d 绘制。此次重做替换了无贴图的箱体、圆柱、圆环以及程序生成的白色材质：所有地面、水面、墙面和景物现在都取自七张原创 RGBA 场景图集。

## 原作构建方法与本作边界

只读参考为 Touhou20Reconstruction 的 scripts/recovered/std/st01.std.txt、st05.std.txt，scripts/recovered/anm/st01wl.anm.txt，以及 source_reconstruction/stage_background 下的相机、雾、投影与脚本模块。STD 的 ENTRY/QUAD 把带不同尺寸、坐标和动画的面片组合为对象，再在场景中放置多个 INSTANCE；相机位置、方向、视场角与雾随时间更新。st01 的地面与分层植被、st05 的重复面组及镜头插值提供了设计依据。

本作借鉴这种“绘制素材组成空间、镜头穿行其中”的方法，未复制锦上京的背景素材、STD 时间表或 ANM。新图集均由内置 image_gen 生成，复制时保持文件字节和透明通道原样。没有使用 Python 绘画、抠图、缩放或重绘；离线读取 alpha 只用于记录 UV 范围。全部七张图的最终尺寸为 1254×1254，尽管生成提示要求 1024×1024，程序按实际尺寸采样。

## 素材与透视

每面独立图集放在 assets/scenery/stage01-atlas.png 至 stage07-atlas.png。每图四格分别是俯视连续地面、标志建筑、侧景和饰物。三格景物保留真实 alpha，地面格不透明。background-art.js 保存逐格实测轮廓范围，并保留至少两像素边缘：运行时直接选取 atlas UV，不生成裁切图片，不把透明边距误作物体的高度。

顶点始终为世界中的 [x,y,z,u,v,color]。横置地面、水面与云层、竖置景物、朝向走廊的书架墙拥有不同朝向和距离。JS 只建立观察、透视和视窗 MVP；GPU 接收原始 Clip W 并执行透视正确的 UV 插值与齐次近远裁剪。没有把三维位置先投影成屏幕精灵，也没有用一张整景画作替代三维前景。

assets/art/stage01.png 至 stage07.png 仍以低亮度提供远处天空、山林或建筑轮廓。移除此远景层，地面、河水、门、树、船、书架、名牌和相机产生的大小变化与视差仍然存在。

## 七面道中与符卡环境

| 关卡 | 道中面片的空间关系 | 独立符卡布景 |
| --- | --- | --- |
| 灯笼坂 | 连续石板路；左右多层松枫；横跨道路的鸟居；两旁灯柱 | 大鸟居、后侧林木与六盏不同深度的灯 |
| 湿墨竹林 | 石路与侧溪在俯视材质中连续；竹丛分前中后层；信亭偏在路侧；信札悬空 | 深处信亭、围出的竹屏、散在不同高度的信札 |
| 无名渡口 | 透视河面；交替出现的横向拱桥；侧向渡船；漂浮水灯 | 一座大拱桥、两侧船、围着水域的十盏灯 |
| 记忆织庭 | 庭院石材；侧方织架；多层梅树；悬在庭上的紫金丝绸 | 成对织架、后层梅花、跨越不同深度的丝绸 |
| 归名书库 | 俯视木地板与中央毯道；两侧沿 Z 延伸并朝内的书架墙；重复门框；悬札 | 更宽更高的书架走廊、尽头门、分层纸札 |
| 无名之庭 | 云中石道；石道下方横置的软云；两侧高大空白名牌；上方铃 | 周围的六块名牌、下层云、中央远处的大铃 |
| 倒铃回廊 | 反射感地材；两侧镜牌；上方倒铃；纵向红白带 | 两侧镜牌、前后错落的低对比红白带、两座倒铃 |

道中镜头持续前进，按面具有不同高度和速度，小幅横移、俯仰制造视差。书库横移较小，Extra 仅有轻微横滚。符卡使用单独的预建布景和缓慢的有限镜头弧线；不围着一张竖面片转整圈，以免露出绘画素材的背面。它们不是道中画面简单换色。

## 图层、雾与性能

公共 mesh3d 不开启深度缓冲。本作使用受约束的场景拓扑：云在石道下、地面在站立面片下，各组内部按相机前向从远到近排序。同一图集允许一个批次内正确排列地面与透明景物；不会把远处灯或信纸另作为最上层屏幕覆盖物。不能仅按面中心深度把地面放到桥脚前面，因此层次首先服从这种明确的上下关系。道路分段再由远到近提交，避免互相穿插的面组。

地面拆成短透视条带，相邻条带共享完全相同的接缝 UV；每个区段以完整的一格地面从近端 v=1 到远端 v=0 连续采样。世界原点跟随道路段重置，使长时间运行仍保持稳定的小矩阵数值。近裁剪交给 GPU，不做接近零 Z 的屏幕坐标除法。

静态顶点、UV、色彩以及有限的九档距离衰减缓存不在每帧重建。道路有三种交替区段，普通场景固定七次 mesh3d 提交、最多 432 个世界顶点；符卡固定一次提交、最多 148 个顶点。每帧只更新相机矩阵与少量面的索引排序。图集首次由 GameArt 加载，生命周期和肖像一致；StageBackground.destroy 只丢弃 CPU 场景，不抢先卸载共享材质。

距离衰减、压低的远景、轻微暗色覆盖控制亮度，弹幕、Boss 法阵、扭曲、题名和计时均由后面的公共层完成。背景不开启或结束 scissor；调用方的 thlib 合成器负责 x=48..624、y=24..696 的场地裁剪，右侧 HUD 位于此三维视窗外。相机只依赖关卡、视觉帧和符卡状态，不使用游戏 RNG，不改回放或碰撞。

## 调用与验证

StageBackground({art}) 接受 GameArt；setStage(stage) 接受 1..7 或关卡对象；draw(draw,game,{stage,clock}) 使用现有队列和视觉时钟；game.spell.active 选择符卡布景。该接口与原调用方兼容。

tests/background.test.js 覆盖矩阵约定、Clip W、近远平面、场地映射、七种空间布景、确定且平稳的航线、UV 邻格安全与地面接缝、书架墙朝向、静态顶点缓存、遮挡层次、长时间坐标以及共享材质生命周期，当前 11 项通过。

tools/verify-background.mjs 可串行捕获七面道中与七个符卡环境，并比较 V8 / QuickJS 的状态和 PNG。后台原生截图及主游戏合成后的弹幕可读性由最终整体验收确认；后端一致本身不能说明审美与原作完全一致。此前白色材质几何版本的截图和性能结果不能用于此次重做的验收。

完整生成提示与工具说明保存于 [SCENERY-PROMPTS.json](SCENERY-PROMPTS.json)，七张最终文件的来源路径及 SHA-256 保存于 [SCENERY-SOURCES.json](SCENERY-SOURCES.json)。这些场景资源属于本作业务内容，随本作走独立素材与同人发布说明，不进入 thlib。
