# 贴图构建的实时三维背景

背景使用游戏自己的 [src/background.js](../src/background.js) 与 [src/background-art.js](../src/background-art.js)，通过 TS-STG 公共 DrawList.mesh3d 绘制。此次重做替换了无贴图的箱体、圆柱、圆环以及程序生成的白色材质：所有地面、水面、墙面和景物现在都取自七张原创 RGBA 场景图集。

## 原作构建方法与本作边界

只读参考为 Touhou20Reconstruction 的 scripts/recovered/std/st01.std.txt、st05.std.txt，scripts/recovered/anm/st01wl.anm.txt，以及 source_reconstruction/stage_background 下的相机、雾、投影与脚本模块。STD 的 ENTRY/QUAD 把带不同尺寸、坐标和动画的面片组合为对象，再在场景中放置多个 INSTANCE；相机位置、方向、视场角与雾随时间更新。st01 的地面与分层植被、st05 的重复面组及镜头插值提供了设计依据。

本作借鉴这种“绘制素材组成空间、镜头穿行其中”的方法，未复制锦上京的背景素材、STD 时间表或 ANM。新图集均由内置 image_gen 生成，复制时保持文件字节和透明通道原样。没有使用 Python 绘画、抠图、缩放或重绘；离线读取 alpha 只用于记录 UV 范围。全部七张图的最终尺寸为 1254×1254，尽管生成提示要求 1024×1024，程序按实际尺寸采样。

## 素材与透视

每面独立图集放在 assets/scenery/stage01-atlas.png 至 stage07-atlas.png。每图四格分别是俯视连续地面、标志建筑、侧景和饰物。三格景物保留真实 alpha，地面格不透明。background-art.js 保存逐格实测轮廓范围，并保留至少两像素边缘：运行时直接选取 atlas UV，不生成裁切图片，不把透明边距误作物体的高度。

顶点始终为世界中的 [x,y,z,u,v,color]。横置地面、水面与云层、竖置景物、朝向走廊的书架墙拥有不同朝向和距离。JS 只建立观察、透视和视窗 MVP；GPU 接收原始 Clip W 并执行透视正确的 UV 插值与齐次近远裁剪。没有把三维位置先投影成屏幕精灵，也没有用一张整景画作替代三维前景。

assets/art/stage01.png 至 stage07.png 仍以低亮度提供远处天空、山林或建筑轮廓。移除此远景层，地面、河水、门、树、船、书架、名牌和相机产生的大小变化与视差仍然存在。

## 动态符卡背景

[src/spell-background.js](../src/spell-background.js) 只负责本作的视觉内容。只读参考是 TS-STG 的 games/rushboss/src/stage-artwork.js：默认竖屏 Demo 在 priority 11 调用 drawSpell，各张卡独立保存 age、scroll、alpha 与 leaving，底纹和另一层流纹按不同方向采样，结束后继续移动并淡出。这里借鉴其分层与生命周期设计，不复制 Rush 的图像、私有代码、魔法阵或扭曲效果。

本作每个 Boss 的动态图形仍使用对应原创场景图集。屏幕流纹是低对比、较大尺度的材质网格；它们连续平移并缓慢旋转。透明主题素材另外批量排列与运动，七种方式如下：

| Boss | 底纹运动 | 主题饰物的运动 |
| --- | --- | --- |
| 扉灯祈 | 铜色地纹向上偏移、缓慢旋转 | 十盏灯沿椭圆绕行，各自微摆 |
| 雨巻静织 | 雨青材质斜向下流 | 十八组信札以不同速度落下，轻摆并转动 |
| 渡守澪舟 | 青绿水纹斜向流动，网格角点轻微波动 | 十二盏水灯绕行，叠加水流起伏 |
| 糸守紫乃 | 梅紫庭纹斜向流动并反向旋转 | 十二组丝绸交错穿过画面并轻摆 |
| 御影房枝 | 墨绿材质缓慢上行 | 十八枚纸札以不同高度、速度和摆角向上穿行 |
| 白识言音 | 薄荷象牙材质横向流动 | 多层云团横向穿行，五座铃绕行且摆动 |
| 玉继未央 | 靛蓝镜纹两层反向流动与旋转，第二层轻叠加 | 红白带与倒铃沿反向的回声轨迹绕行 |

Extra 的中 Boss 是房枝，其动态图形按实际 bossId 使用书库主题，不误用未央的倒铃。素材借用 GameArt 的 atlas 缓存，不加载锦上京或 Rush 的符卡专属资源，不创建新纹理或渲染目标。网格每块 UV 都限制在对应 atlas 格内；滚动通过移动重复的材质网格实现，不能用整个 atlas 的 wrap 把相邻鸟居、树和饰物采进地纹。

一次符卡开始后，背景用 48 个模拟帧进入；结束后以结束时的实际透明度继续运动，并在 24 帧内退出。下一张可以在旧背景淡出时开始，两张独立保存时钟与透明度，最多保留两张。换关和销毁清理全部视觉状态。背景不会作为 TouhouSpell.background 传入：公共符卡 finish 会立即销毁该 ANM，并在不同的公共绘制路径提交它，这会破坏当前淡出与背景捕获边界。

StageBackground.update 在成功的游戏帧更新后读取 spell.active、符卡标识与 context.boss.bossId；暂停时既不更新背景时间，也不处理生命周期。draw 只读取该帧，即使暂停菜单重复渲染、截图多次采样，所有流纹、饰物、相机和退出透明度都保持不动。第一次直接渲染已开始的练习卡可以做一次初始化同步；此后独立调用方必须 update。相位由注入 seed 和稳定符卡标识计算，未使用 Date.now、Math.random 或游戏 RNG。

## 图层、雾与性能

公共 mesh3d 不开启深度缓冲。本作使用受约束的场景拓扑：云在石道下、地面在站立面片下，各组内部按相机前向从远到近排序。同一图集允许一个批次内正确排列地面与透明景物；不会把远处灯或信纸另作为最上层屏幕覆盖物。不能仅按面中心深度把地面放到桥脚前面，因此层次首先服从这种明确的上下关系。道路分段再由远到近提交，避免互相穿插的面组。

地面拆成短透视条带，相邻条带共享完全相同的接缝 UV；每个区段以完整的一格地面从近端 v=1 到远端 v=0 连续采样。世界原点跟随道路段重置，使长时间运行仍保持稳定的小矩阵数值。近裁剪交给 GPU，不做接近零 Z 的屏幕坐标除法。

静态顶点、UV、色彩以及有限的九档距离衰减缓存不在每帧重建。道路有三种交替区段，普通场景固定七次 mesh3d 提交、最多 432 个世界顶点。符卡每张另提交一次不超过 148 顶点的三维布景、两次动态材质/饰物网格；未央再增加一次反向流纹。稳态符卡共 10 次提交，未央 11 次；两张进退交叠最多 15 次、总顶点少于 2,300。动态部分只有数百顶点，不在每帧重建静态道路和建筑。图集首次由 GameArt 加载，生命周期和肖像一致；StageBackground.destroy 只丢弃 CPU 场景与动态卡状态，不抢先卸载共享材质。

距离衰减、压低的远景、轻微暗色覆盖控制亮度。全部动态内容位于业务背景捕获层，公共 Boss 双圈、14/15 背景扭曲随后基于已完成的捕获画面合成；弹幕、题名、计时和 HUD 保持原公共优先级。背景不开启或结束 scissor，也不持有独立渲染目标；调用方的 thlib 合成器负责 x=48..624、y=24..696 的场地裁剪，右侧 HUD 位于此三维视窗外。每个混合范围均关闭，不把动态纹理画到 UI 或弹幕上。

## 调用与验证

StageBackground({art,seed}) 接受 GameArt 与可选的确定种子；setStage(stage) 接受 1..7 或关卡对象；update(game,{clock,bossId}) 的默认值是 game.frame 和 game.context.boss.bossId，必须在成功的未暂停模拟更新后调用；draw(draw,game,{stage,clock}) 使用现有队列采样该视觉帧。game.spell.active 选择符卡状态。接口的旧参数仍兼容，动态效果的推进通过新增 update 显式完成。

tests/background.test.js 当前 14 项通过，覆盖矩阵约定、Clip W、近远平面、场地映射、七种空间布景与真实纹理运动、稳定 seed/clock、重复渲染与暂停冻结、48/24 帧进入退出、实际中 Boss 主题、连续卡数量与提交上限、UV 邻格安全和地面接缝、书架墙朝向、静态顶点缓存、遮挡层次、长时间坐标以及共享材质生命周期。七种主题各在相距 120 帧的样本中验证动态 mesh 明确变化，其变化不依赖三维相机 MVP。

tools/verify-background.mjs 可串行捕获七面道中与七个符卡环境，并比较 V8 / QuickJS 的状态和 PNG。后台原生截图及主游戏合成后的弹幕可读性由最终整体验收确认；后端一致本身不能说明审美与原作完全一致。此前白色材质几何版本的截图和性能结果不能用于此次重做的验收。

动态版本的背景专用原生检查已运行七面 × 道中/符卡 × V8/QuickJS，每个样本 240 帧，共 28 次短运行。14 对 PNG 哈希严格相同；状态整数严格相同，镜头三角函数采用相对 1e-12 容差。实际样本最多 11 次提交、1,108 顶点。全部十四种画面已检查，没有发现 UV 黑边、邻格串色或透明方框。另保留灯坂、织庭、云庭与倒铃在 120 帧的样本，与 240 帧比较，能看到灯位、丝绸走势、云铃位置、倒铃与红白带角度的变化。报告位于被 Git 忽略的 reports/backgrounds/report.json、motion-comparison.json 与 reports/backgrounds-frame120/。这些结果只验证背景模块，不能替代主游戏的弹幕对比、题名层级和法阵扭曲检查，也不是完整游戏的性能数据。

完整生成提示与工具说明保存于 [SCENERY-PROMPTS.json](SCENERY-PROMPTS.json)，七张最终文件的来源路径及 SHA-256 保存于 [SCENERY-SOURCES.json](SCENERY-SOURCES.json)。这些场景资源属于本作业务内容，随本作走独立素材与同人发布说明，不进入 thlib。
