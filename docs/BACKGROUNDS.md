# 实时三维背景

[`src/background.js`](../src/background.js) 是游戏自己的场景模块。它使用 TS-STG 的公共 `DrawList.mesh3d`；没有修改引擎或引擎副本，也没有把原创场景放入 thlib。

`new StageBackground({art})` 接受 `GameArt`。`setStage(stage)` 选择关卡，`draw(draw,game,{stage,clock})` 接收现有绘制队列与确定的视觉时钟。`game.spell.active` 为真时绘制该角色的三维符卡舞台。`destroy()` 只释放模块自己创建的材质图集，远景画作仍由 `GameArt` 管理。

## 三维边界

道路、河面、桥、鸟居、竹子、织架、书架、书、台阶、名牌柱、镜面柱和铃均由真正的 `[x,y,z,u,v,color]` 世界顶点组成。JS 创建列主序观察、透视与视窗矩阵；GPU 接收 MVP，并保留 Clip W，执行透视正确的 UV 插值与近远裁剪。没有先在 JS 中把三维点压成二维精灵位置。

画布为 960×720；归一化的 Clip XY 映射到游戏场地 x=48..624、y=24..696。场景应由 thlib 的背景合成器限制在游戏场地。右侧 HUD 不属于三维视窗，倒计时、符卡题名、Boss 血环与玩家等由后续公共层绘制。

生成的 `assets/art/stage01..07.png` 只作为低亮度的天空、山林或远景层。移除这些画作以后，场地中的三维建筑、地面、相机透视与前后遮挡依旧完整存在。

## 七个场景

| 关卡 | 世界中的立体结构 | 相机与细节 |
| --- | --- | --- |
| 灯笼坂 | 石板小路、双柱多梁鸟居、铜色纸灯、树干与树冠 | 贴着小路前进并缓慢横移；暖色灯面与微小漂浮光点 |
| 湿墨竹林 | 有竹节的多边形竹干、叶片、侧边溪水、悬挂信纸 | 从高竹之间低空前进；与相机朝向一致的细雨 billboard |
| 无名渡口 | 河面、逐段升高的拱桥与护栏、船体与船桨、水灯、河岸 | 稍高视角沿水路行进；清楚的拱桥曲面与远处雾色 |
| 记忆织庭 | 带经纬的织架、跨越庭院的金丝、梅紫鸟居、树 | 金丝跨越实际三维空间；相机向前穿过不同深度的织架 |
| 归名书库 | 有实体侧板、背板、隔板和书籍的书架、立柱、横梁、悬札 | 保留中央走廊，较小的横向摆动；实体书脊有不同高度与颜色 |
| 无名之庭 | 云上石阶、带留白正面的名牌柱、基座、立体铃、远侧圆台 | 高空平稳推进；薄荷与象牙配色，避免遮住弹幕 |
| 倒铃回廊 | 镜柱、反光斜条、红白空间飘带、上方横梁、成对铃 | 银白靛蓝的固定走廊中有稍不对称的空间；不使用恐怖意象 |

符卡阶段围绕一个立体圆台缓慢环绕。每个角色保留自己的结构：灯环与鸟居、竹与信纸、桥与小船、织架与跨场丝线、书架与方印、名牌柱与大铃、镜柱与正逆声环。它们是独立三维网格，不是普通道中画面的染色副本。符卡图层仍服从 thlib 的 Boss 法阵、背景扭曲和题名机制。

## 无深度缓冲的前后顺序

公共 `mesh3d` 不开启深度缓冲。因此每个网格保存各面的中心，按照当前相机前向上的深度从远到近排列三角形索引。普通场景再把七段相同世界长度的道路由远到近提交。每段中的实体面和少量透明 billboard 共用材质，合在同一次深度排序里，不把远处光点单独覆盖到近处建筑上。

没有深度缓冲的画家算法不适合任意互相穿插的复杂网格；本作建筑位置、细线和书架间距避免这种拓扑。近裁剪使用齐次 Clip W，而不是把摄像机后方的点除以接近零的 Z，从而不会出现巨大拉伸的二维三角形。

## 性能与一致性

静态世界顶点、UV、顶点光照与有限的六档距离雾配色均缓存。道路具有三种预建分段：桥不会每一段都出现，灯坂、竹林等地标间距也交替变化。小型材质图集的左半是细纸石纹，右半是边缘透明的柔光；实体与飘粒共用一张材质仍能正确排序。每帧改变相机 MVP，排序面的中心，并生成少量相机朝向的漂浮粒子。不会每帧重新建造树、书架或数万个世界顶点。普通阶段最多七个 `mesh3d` 命令、不超过 9,996 个 GPU 顶点；符卡阶段一次命令、不超过 1,552 个顶点。场景切换只保留当前道中与当前符卡舞台，避免所有关卡的网格副本常驻累积。

雾色与顶点灯光是场景配色的一部分，远处结构逐渐向低对比背景色收敛。画作亮度压低，游戏场地顶部再轻微压暗，保证弹幕、法阵、倒计时与题名清晰。三维相机与粒子只依赖关卡、视觉帧和符卡状态，不消耗游戏 RNG，也不影响回放。

`tests/background.test.js` 验证矩阵约定、透视 Clip W、近远平面、游戏场地映射、七种几何、轨迹重复性、合法网格命令、透明面的排序、道路段接缝与资源释放。`tools/verify-background.mjs` 可使用现有原生引擎串行捕获七面道中和符卡画面；后端一致不能代替主游戏中的画面验收。

本次验收运行了 9 项背景测试，并捕获七面道中与七面符卡舞台，共 14 组 V8 / QuickJS 成对场景。每组运行 24 帧，状态与 PNG 哈希完全一致，所有截图已检查。背景专用性能样本另用顶点较多的第二面运行 600 帧，排除前 60 帧资源预热：V8 的帧工作平均 4.15 ms、95 分位 4.76 ms，QuickJS 平均 5.33 ms、95 分位 5.80 ms；V8 的 JS 场景绘制约 0.24 ms，其余主要是公共命令解码。这是本机背景专用 fixture 的数据，主游戏还须计入弹幕、自机、Boss 与 UI 的开销。报告在未纳入 Git 的 `reports/backgrounds/`。
